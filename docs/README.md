# Documentation

Verity can be self-hosted for a team or evaluated locally. Publishing the source
repository makes these guides readable without an account. A running Verity
installation still requires a user account and vault access to read project data;
there is no anonymous vault-sharing mode.

| I want to… | Start here |
| --- | --- |
| Run Verity locally | [Quick start](../README.md#quick-start-with-docker) |
| Create my first project and work with a team | [User guide](user-guide.md) |
| Make the app reachable on a public HTTPS domain | [Installation and deployment](../INSTALL.md#public-https-deployment) |
| Understand every configuration setting | [Configuration reference](configuration.md) |
| Back up, restore, upgrade, or recover access | [Operations](operations.md) |
| Diagnose an installation or access problem | [Troubleshooting](troubleshooting.md) |
| Integrate with the REST API | [API reference](../backend/doc/api.md) and [runnable example](examples/api_quickstart.py) |
| Understand permissions and stored data | [Data model](../backend/doc/data-model.md) |
| Report an issue or contribute code | [Contributing](../CONTRIBUTING.md) |
| Report a security issue privately | [Security policy](../SECURITY.md) |

The application also has a **Help** button with context-specific guidance.
These guides describe the source revision beside them. When using an older
revision, read the documentation from that same checkout.
